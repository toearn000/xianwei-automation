# 仙位挑战自动化（xianwei-automation）

> 某 4399 MMORPG 页游「竞技场日常」的全自动执行引擎：通过 CDP 远程控制真实
> Edge 浏览器，用「截图 → 像素级状态识别 → 比例坐标点击」的闭环，把每日 5 场
> 竞技挑战压缩到 **1 分钟以内、零人工干预** 完成。

## 解决的问题

- 该页游的「仙位挑战」是每日 5 场的竞技场日常，手动完成一次需要反复
  点击、盯画面、处理随机弹窗（段位提升 / 惊喜掉落 / 刷新确认），单账号约
  10 分钟，多账号成本线性上升。
- 游戏运行在 Canvas 里，没有 DOM 可操作；又是页游外挂高危区，不适合
  注入脚本，只能走「外部观察 + 外部操作」路线。
- 浏览器窗口会被用户缩放、DPR 不是 1、弹窗随机出现且会吞掉点击——
  任何一个环节不健壮，自动化就会变成「自动出错」。

## 方案架构

```
┌─────────────────────────────────────────────────────────┐
│  zmws.py（单文件引擎，742 行，无第三方 UI 依赖）           │
│                                                         │
│  子命令层   rect / shot / click / badges / state        │
│             scan / clickscan / mode / config / xianwei  │
│  ─────────────────────────────────────────────────────  │
│  状态机     opponent_list · victory · rankup · drop     │
│             · confirm · unknown                         │
│  ─────────────────────────────────────────────────────  │
│  视觉识别   红章检测 / 亮橙按钮检测 / 绿色按钮检测         │
│             （numpy 像素占比 + 亮度双阈值）               │
│  ─────────────────────────────────────────────────────  │
│  坐标系     iframe 比例坐标 (fx,fy) → CSS px → 物理像素  │
│             （每次执行现取 rect + dpr，窗口缩放安全）     │
└──────────────┬──────────────────────────────────────────┘
               │ HTTP JSON
┌──────────────▼──────────────────────────────────────────┐
│  WebBridge daemon（http://127.0.0.1:10086/command）      │
│  evaluate / screenshot / cdp(Input.dispatchMouseEvent)  │
└──────────────┬──────────────────────────────────────────┘
               │ CDP
┌──────────────▼──────────────────────────────────────────┐
│  真实 Edge 浏览器（用户态登录，非模拟器、非注入）          │
└─────────────────────────────────────────────────────────┘
```

核心思路：**观察与操作都走浏览器标准调试协议（CDP），脚本在浏览器之外**。
游戏完全感知不到自动化存在；所有「看懂画面」的工作由像素级颜色统计完成，
不依赖 OCR、不依赖截图模板匹配，速度快且对分辨率变化鲁棒。

## 核心技术指标（真实验收数据）

| 场景 | 账号战力 | 结果 | 耗时 | 备注 |
|---|---|---|---|---|
| 最终验收 | 320 万 | 5 场全胜打满 | **53.4 秒** | 0 次刷新；自动处理 2 次段位提升弹窗 + 1 次惊喜掉落 + 1 次画面抖动自愈 |
| 低战力账号 | 44 万 | 2 场全自动完成 | 38.5 秒 | 过程中发现并自动修复了「刷新消耗确认弹窗」新状态 |
| 半自动提速版 | 537 万 | 5 场全胜 | 5 分 46 秒 | 合并子命令前的逐步模式 |
| 离线回放 | — | 5 种历史截图状态判定 | **100% 正确** | 对手列表/胜利/段位提升/掉落/确认弹窗 |

对比基线：手动单账号约 10 分钟 → 全自动 **53 秒**，提速约 11 倍，且全程零干预。

## 工程亮点

- **真实浏览器远程控制**：通过 CDP/WebBridge 控制用户真实 Edge 浏览器
  （用户态登录态），不是模拟器、不注入游戏页面，规避页游反外挂检测面。
- **像素级状态识别**：不做 OCR、不做模板匹配，用 numpy 对采样区域做颜色
  占比统计（如「碾压」红章的红色占比 ≥ 0.30、对手战力红字占比阈值 0.05），
  配合区域平均亮度区分「亮着的按钮」与「被弹窗压暗的背景」。全部阈值来自
  实战截图标定（标定过程与样本数据保留在代码注释中）。
- **画面状态机 + 弹窗自愈**：6 态状态机（对手列表/胜利/段位提升/惊喜掉落/
  刷新确认/未知），随机弹窗自动识别、自动关闭、自动续接主流程；
  「确认弹窗只在上一步是刷新时才自动点确定」的防呆设计，避免误点付费操作。
- **配置驱动的双选卡策略**：`high_power`（只打奖励最高的第 4 卡，不行就刷新）
  与 `low_power`（打最右可碾压卡）按账号战力切换；刷新次数上限可配
  （付费刷新成本递增很陡，实测 1000 → 50000 游戏币，低战力号需限流）。
- **进程级性能优化**：把「点击 + 等待 + 截图 + 状态判定」合并为一次进程调用
  （`clickscan`），全自动循环（`xianwei` 子命令）实现 5 场战斗**零上层往返**；
  剩余次数本地计数，不为读数额外截图。
- **坐标体系鲁棒性**：所有点击用相对游戏 iframe 的比例坐标，每次执行现取
  `getBoundingClientRect()` + `devicePixelRatio`（实测 DPR=1.5），窗口缩放、
  移动均不炸坐标；禁止硬编码绝对像素。
- **工程细节**：OpenBLAS 多线程在部分机器上导致内存分配崩溃，在 numpy 导入前
  强制 `OPENBLAS_NUM_THREADS=1`；所有未知画面存图停机交回人工，绝不死循环盲猜。

## 快速开始

```bash
# 环境：Python 3.x + numpy + pillow + requests；
#       Edge 浏览器已安装 WebBridge 扩展，daemon 监听 127.0.0.1:10086
cp src/config.example.json config.json   # 脚本读取自身上级目录的 config.json

python src/zmws.py rect                  # 取游戏 iframe 矩形 + dpr
python src/zmws.py scan out.jpg          # 截图 + 状态判定一步完成
python src/zmws.py clickscan 0.886 0.849 2 out.jpg   # 点击+等待+截图+判定
python src/zmws.py mode high             # 切换高战力选卡策略
python src/zmws.py xianwei 5 ./work      # 仙位挑战全自动循环（5 场）
```

> 说明：坐标比例表与状态判定规则是针对该游戏画面标定的，换游戏需要重新
> 标定坐标与颜色阈值（标定方法见 `docs/architecture.md` 与代码注释）。
